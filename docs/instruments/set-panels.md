# Set document: shipped flight panels

This document describes the `indicate-instrument-panels` crate, which
exports two sets: the flight set `builtin` (PFD, HSI, autoflight,
monitor) and the configuration set `config`. The
[panel contract](panel-contract.md) states what every set owes; this
document states what these sets are for, what they draw, how they fail,
and which requirements they answer to. The descriptor facts at the end
are generated from the code and checked in CI.

## Intended function

Every panel is a **SIM / NOT FOR FLIGHT** simulator display
([`AIR-BAS-001`](requirements.md#air-bas-001)) with a conservative
dual-pilot Part 25 IFR flight deck as its architecture reference
([`AIR-BAS-002`](requirements.md#air-bas-002)).

- `pfd` supplies supplemental attitude, air-data, altitude, and
  guidance awareness under
  [`AIR-OUT-001`](requirements.md#air-out-001), in conventional,
  synthetic-vision, unusual-attitude, and degraded modes
  ([`AIR-MODE-001`](requirements.md#air-mode-001) through
  [`AIR-MODE-004`](requirements.md#air-mode-004)).
- `hsi` supplies supplemental heading and navigation awareness under
  [`AIR-OUT-002`](requirements.md#air-out-002), with no navigation or
  approach credit.
- `autoflight` reports what the automation holds and what it is armed
  to hold, from [`AIR-IN-015`](requirements.md#air-in-015); it grants
  no command-guidance credit.
- `monitor` is the advisory text surface for machine status under
  [`AIR-IN-014`](requirements.md#air-in-014); it never poses as a
  flight instrument.
- `config` reports sensed flap position and elevator trim from
  [`AIR-IN-016`](requirements.md#air-in-016); a selected detent is never
  shown in place of a sensed position.

The configuration set is separate so that a shell composes it only when
the airframe has the sensors, and so that the composition digest of the
flight set does not move for a panel most airframes do not show.

## Inputs

Each panel requires the groups listed in its descriptor facts. Inputs
arrive under [`AIR-IN-001`](requirements.md#air-in-001) through
[`AIR-IN-009`](requirements.md#air-in-009) for flight state, time, and
validity evidence; alerts under [`AIR-IN-012`](requirements.md#air-in-012);
renderer health under [`AIR-IN-013`](requirements.md#air-in-013). Only
the PFD takes configuration: background mode, V-speeds, and the
synthetic-vision viewport and quality. Admission draws every panel with
the empty configuration, so no numeral may derive from it.

## Failure presentation

The presentation is uniform across the crate
([`AIR-OUT-004`](requirements.md#air-out-004)):

- `Missing` paints dashes that carry no provenance claim
  ([`AIR-FLAG-004`](requirements.md#air-flag-004)).
- `Stale` and `Degraded` keep the value and paint an amber flag through
  the shared status paint ([`AIR-FLAG-002`](requirements.md#air-flag-002),
  [`AIR-FLAG-003`](requirements.md#air-flag-003)).
- `Failed` paints a full-frame red X through the shared status paint
  ([`AIR-FLAG-005`](requirements.md#air-flag-005)).
- Attitude, air data, altitude, and heading each fail their own
  function under [`AIR-UNAV-001`](requirements.md#air-unav-001) through
  [`AIR-UNAV-003`](requirements.md#air-unav-003); the PFD's
  synthetic-vision background cedes to the conventional horizon under
  [`AIR-UNAV-005`](requirements.md#air-unav-005).
- The monitor fails its channel visibly on malformed or stale text and
  never retains last-good rows.

The safety colours come from `indicate-instrument-symbology::safety`
and no theme can change them.

## Composition

The four flight panels carry pinned raster baselines and measured
criticality bands, so a screen may compose them under
[`AIR-OUT-011`](requirements.md#air-out-011). The bench shell in
`tools/instrument-bench` composes a PFD, HSI, and monitor screen and
reproduces the pinned screen-composition digest.

## Verification

- Admission and digest: `cargo test -p indicate-instrument-panels` runs
  the set through the admission harness (from the conformance crate's
  own tests) and pins the scene digest.
- Reference frames: `cargo test -p indicate-instrument-raster` asserts
  every panel's pinned frame hash (REN-03).
- Layer profile: `layer_profile_doc_tests` holds the required-layer
  table in [the scene-layer protocol](scene-layer-protocol.md) equal to
  the descriptors.
- Pixels: `cargo run -p instrument-bench -- --out <dir>` writes every
  panel × canonical state × canonical frame as PPM files.
