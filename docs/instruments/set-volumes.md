# Set document: three-dimensional volumetric instruments

This document describes the `indicate-instrument-volumes` set.
The [panel contract](panel-contract.md) states what every set owes.
This document states what this set draws, how it fails, and which requirements it answers.
The code generates the descriptor facts at the end, and CI checks them.

## Intended function

The `volumes` set is a **SIM / NOT FOR FLIGHT** demonstration surface ([`AIR-BAS-001`](requirements.md#air-bas-001), [`AIR-MODE-007`](requirements.md#air-mode-007)).
It provides three spatial instruments in a bounded three-dimensional volume (`VOL-01`):

- **Terrain volume** (`terrain-volume`).
  It renders a terrain mesh, an aircraft marker, a waypoint path, and an optional two-dimensional status overlay ([`AIR-OUT-005`](requirements.md#air-out-005)).
- **Globe volume** (`globe-volume`).
  It renders a planetary wireframe sphere, navigation route polylines, waypoint billboards, and an optional two-dimensional overlay ([`AIR-OUT-002`](requirements.md#air-out-002)).
- **Orrery volume** (`orrery-volume`).
  It renders celestial body markers, orbital polylines, a vehicle vector, and an optional two-dimensional overlay ([`AIR-OUT-005`](requirements.md#air-out-005)).

The set supplies supplemental spatial awareness in a simulator.
It provides no synthetic-vision guidance credit and no terrain-alerting function ([`AIR-OUT-009`](requirements.md#air-out-009), [`AIR-OUT-010`](requirements.md#air-out-010)).

## Inputs and spatial interaction

Each instrument consumes one resolved aircraft snapshot and one central alert snapshot per frame.
Attitude, position, altitude, velocity, air data, and navigation arrive under [`AIR-IN-001`](requirements.md#air-in-001) through [`AIR-IN-005`](requirements.md#air-in-005).
Time and per-signal validity evidence arrive under [`AIR-IN-008`](requirements.md#air-in-008) and [`AIR-IN-009`](requirements.md#air-in-009).
Independent alerts arrive under [`AIR-IN-012`](requirements.md#air-in-012).

Each instrument also reads one optional auxiliary channel for external geometry ([`AIR-IN-011`](requirements.md#air-in-011)):

- `terrain-volume` reads `TERRAIN_PATCH_3D` (`0x0010`).
- `globe-volume` reads `GLOBE_NAVIGATION_3D` (`0x0011`).
- `orrery-volume` reads `CELESTIAL_EPHEMERIS_3D` (`0x0012`).

The host supplies a three-dimensional view pose (`IXN-01`) and a half-extent volume box for each frame.
Orbit, pan, zoom, and reset interactions rotate or scale the view pose without altering aircraft state ([`AIR-HAZ-008`](requirements.md#air-haz-008)).

## Failure presentation

Every billboard numeral carries the provenance group of the state signal it formats ([`AIR-IN-009`](requirements.md#air-in-009)).
When a required group is `Missing`, the instrument withholds dependent numerals and paints dashes without provenance ([`AIR-FLAG-004`](requirements.md#air-flag-004)).
`Stale` and `Degraded` signals keep their values and display explicit status labels ([`AIR-FLAG-002`](requirements.md#air-flag-002), [`AIR-FLAG-003`](requirements.md#air-flag-003)).
A `Failed` group removes invalid spatial geometry and paints failure red labels ([`AIR-OUT-004`](requirements.md#air-out-004), [`AIR-FLAG-005`](requirements.md#air-flag-005), [`AIR-UNAV-005`](requirements.md#air-unav-005)).
A malformed auxiliary payload returns `PanelDrawError::InvalidAux` and draws no partial scene ([`AIR-BAS-004`](requirements.md#air-bas-004)).
The host presents renderer or output failures under [`AIR-UNAV-007`](requirements.md#air-unav-007).
