# Set document: the template set

This document describes the `indicate-instrument-template` set, the
smallest set that passes admission. It exists to be read and copied;
its own test admits it in CI, so the worked example cannot drift from
the [panel contract](panel-contract.md). The descriptor facts at the
end are generated from the code and checked in CI.

## Intended function

The template is a **SIM / NOT FOR FLIGHT** demonstration surface
([`AIR-BAS-001`](requirements.md#air-bas-001),
[`AIR-MODE-007`](requirements.md#air-mode-007)). It draws one label and
one airspeed readout so that every honesty rule of the contract is
exercised by a panel an author can hold in one screen: a numeral that
carries its provenance claim, a dash that carries none, a background
claim that admission proves, and a region that admission asserts is
populated.

## Inputs

The readout consumes the air-data group under
[`AIR-IN-004`](requirements.md#air-in-004) and folds source trust from
[`AIR-IN-009`](requirements.md#air-in-009); both groups are declared so
that withholding either one is exercised by admission.

## Failure presentation

When the airspeed does not show a value the readout paints `---` in
failure red with no provenance claim
([`AIR-OUT-004`](requirements.md#air-out-004),
[`AIR-FLAG-004`](requirements.md#air-flag-004)). Nothing else is drawn,
which is what makes the example short; a shipped panel adds the flag
and red-X presentation from the shared status paint.

## Verification

`cargo test -p indicate-instrument-template` composes the set, runs the
admission harness, and pins the out-of-frame ink count at zero.
